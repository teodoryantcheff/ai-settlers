# The Settlers — Game Specification

This document describes the implemented game and its current rules. Source code in `src/` is the implementation; generated bundles and artwork are deployment assets.

Production Pages packaging (`npm run build:pages`) isolates deployable files in `dist/`. The entry page points to a content-hashed release directory containing the minified bundle and complete painted art pack, with their relative paths preserved. The release hash covers code, manifest, artwork and provenance; immutable caching applies only to these versioned paths. HTML revalidates, missing paths return a real 404, and soft-launch security/noindex headers are supplied through Pages `_headers`. Simulation, rendering and browser-local save behavior are unchanged. Production deployment runs lint, typechecking, the strict-null-check gate (errors fail outside a shrink-only exclusion list) and Node tests through `npm test`, then a fresh build and package through `npm run build:pages`; the full browser suite remains an explicit separate check. Pull-request and `main` CI runs the format check and `npm test` on the minimum supported Node and never deploys; automated publishing could upload the same package; native Pages Git integration requires a new project rather than converting the initial Direct Upload project.

## Game and objective

The game is a peaceful desktop browser economy and logistics simulation. The player places buildings, connects routes and balances supplies; settlers carry materials, construct buildings and transport output automatically. Outposts expand territory. There are no enemies, combat, starvation deaths or defeat condition.

Victory occurs when the treasury holds **200 gold**. Gold mined into a producer's stock is not yet banked: delivery to storage increases the treasury. Contract rewards also increase it, and buying upgrades reduces it. Lifetime delivered gold is tracked separately. After the victory screen, the player can continue settling.

A new colony begins with a headquarters, eight carriers and these stored goods:

| Good       | Amount |
| ---------- | -----: |
| Planks     |     48 |
| Stone      |     48 |
| Provisions |     20 |
| Tools      |     16 |
| Weapons    |      6 |

The simulation starts paused behind the start screen. The player can start manually or enable autoplay.

## World and generation

The map contains **96 × 96 tiles**, with a logical tile size of 24 pixels. Buildings and units use tile coordinates; zoom and display resolution do not change the simulation.

| Terrain  | Movement   | Building rules                                             |
| -------- | ---------- | ---------------------------------------------------------- |
| Meadow   | Passable   | Normal building ground; may contain trees, rocks and roads |
| Sand     | Passable   | Fishermen may stand here                                   |
| Water    | Impassable | No buildings                                               |
| Mountain | Impassable | Deposits are mined from an adjacent meadow tile            |

The `?seed=N` URL parameter selects a reproducible generation seed. Without it, the game chooses one. Map generation and gameplay randomness are seeded separately. Cosmetic painting, weather and audio do not consume gameplay randomness.

Generation combines noise terrain with a central clearing, a nearby mature forest and rocks, shore access, and an eastern mining ridge containing coal, iron and accessible gold faces. The two guaranteed gold faces together contain at least 440 gold. Accepted maps have at least three reachable gold deposits and at least 440 reachable gold in total. A grass strip beside the eastern face permits mine placement. Generation checks passable-land reachability and retries invalid maps deterministically.

Trees have four growth stages; lumberjacks harvest stages three and four. Ambient growth samples 40 tiles every 0.1 simulation seconds and advances eligible trees with a seeded 50% chance. Foresters plant stage-three trees. Rocks and mineral deposits are finite. Each mining cycle removes one unit from a matching neighboring deposit; mineral seams disappear when depleted. A depleted mine stops working. Quarries remove rock stock until the tile is exhausted.

## Buildings and production

There are seventeen goods: logs, planks, stone, provisions, fish, grain, flour, bread, pigs, meat, beer, coal, iron ore, iron bars, gold, tools and weapons. Provisions retain the legacy `food` key and remain edible; new food producers make distinct goods. Stored goods, reserved goods, producer input stocks and output awaiting delivery are distinct quantities.

The table gives base production cycles in simulation seconds, before upgrades. A work radius is a Euclidean resource-search radius. Completed buildings with a listed claim radius also contribute territory, subject to impassable terrain.

| Building       | Construction cost           | Work / claim radius        | Base operation                                                     |
| -------------- | --------------------------- | -------------------------- | ------------------------------------------------------------------ |
| Headquarters   | Starting building           | Claim 10                   | Storage                                                            |
| Warehouse      | 4 planks, 3 stone           | Claim 8                    | Storage; adds eight carrier capacity                               |
| Lumberjack     | 2 planks, 1 tool            | 6                          | Harvest one eligible tree for 2 logs every 7 seconds               |
| Forester       | 2 planks, 1 tool            | 6                          | Replant around the nearest completed lumberjack                    |
| Quarry         | 2 planks, 2 stone, 1 tool   | 5                          | Produce 1 stone every 8 seconds from rock stock                    |
| Fisherman      | 2 planks, 1 tool            | 5                          | Produce 1 fish every 9 seconds; requires nearby water              |
| Grain Farm     | 3 planks, 2 stone, 1 tool   | 4                          | Produce 1 grain every 15 seconds                                   |
| Coal Mine      | 3 planks, 3 stone, 1 tool   | 2                          | Consume 1 edible good; produce 1 coal every 12 seconds             |
| Iron Mine      | 3 planks, 3 stone, 1 tool   | 2                          | Consume 1 edible good; produce 1 iron ore every 14 seconds         |
| Gold Mine      | 3 planks, 3 stone, 1 tool   | 2                          | Consume 1 edible good; produce 1 gold every 16 seconds             |
| Sawmill        | 3 planks, 1 stone, 1 tool   | No claim                   | Consume 2 logs; produce 1 plank every 8 seconds                    |
| Windmill       | 3 planks, 2 stone, 1 tool   | No claim                   | Consume 1 grain; produce 1 flour every 10 seconds                  |

| Butcher        | 3 planks, 2 stone, 1 tool   | No claim                   | Consume 1 pig; produce 1 meat every 12 seconds                     |
| Well           | 1 plank, 2 stone            | Service radius 6; no claim | Supplies local water without transport                             |
| Brewery        | 3 planks, 2 stone, 1 tool   | Well service required      | Consume 1 grain; produce 1 beer every 18 seconds                   |
| Smelter        | 3 planks, 3 stone, 1 tool   | No claim                   | Consume 1 iron ore and 1 coal; produce 1 iron bar every 16 seconds |
| Basic Workshop | 3 planks, 2 stone           | No claim                   | Consume 2 planks and 1 stone; produce 1 tool every 30 seconds      |
| Toolsmith      | 3 planks, 2 stone, 1 tool   | No claim                   | Consume 1 iron bar and 1 plank; produce 1 tool every 18 seconds    |
| Armory         | 3 planks, 2 stone, 1 tool   | No claim                   | Consume 1 iron bar and 1 coal; produce 1 weapon every 22 seconds   |
| Outpost        | 2 planks, 2 stone, 1 weapon | Claim 3 unmanned, 7 manned | Receives a soldier and expands territory                           |

A forester plants within radius five of its nearest completed lumberjack while that lumberjack's radius-six tree supply is below 20. Without a completed lumberjack, it plants within its own radius six while its radius-seven supply is below 25. Eligible planting sites must be owned, clear meadow. A planting attempt normally repeats every seven seconds; sufficient tree supply delays the next check by five seconds.

Construction starts only when the placement is valid and enough connected, unreserved stock is available. Carriers deliver the full cost to the site. Once all materials arrive, construction takes ten simulation seconds. Output capacity is eight goods; a producer waits when the next output would exceed that capacity. Producers preserve unfinished work while paused or waiting for inputs.

Demand controls keep unnecessary production from absorbing transport and materials:

- Fishermen, bakeries and butchers pause when their own stored output reaches the greater of `6 + 2 × live mines` and the colony's requested reserve for that good. Separate thresholds allow different food types to coexist. Grain farms continue producing grain for all three chains.
- Toolsmiths and basic workshops stop when stored tools reach the greater of 12 and requested tool reserves. Basic workshops also preserve a minimum of four banked planks.
- Grain production pauses at 24 stored grain; flour, pigs and iron bars pause at 12 stored units. Each limit rises to the colony’s requested reserve for that good, and production resumes when stores fall below it.
- Breweries stop when stored beer reaches the greater of 12 and requested beer reserves.
- Armories stop when stored weapons reach the greater of 15 and requested weapon reserves.

These demand pauses are distinct from missing ingredients, exhausted resources and output congestion. Only mines consume food; settlers do not. Fish, bread, meat and legacy provisions each satisfy one mining cycle. Grain, flour, pigs and beer are not edible mine inputs. Mines buffer up to three of each available edible good, consuming the most plentiful local kind with a stable tie order. They gain 5% mining speed per additional edible kind present in their input stock, capped at 10%. The bonus affects mining timers only and uses no randomness.

Bakeries and breweries require a completed well within Euclidean radius six on connected passable land. Wells do not claim territory or produce transported water. Removing a well pauses dependent production without consuming ingredients or losing unfinished work. Grain can instead supply windmills, pig farms or breweries; this creates competing demands on farm output. Beer is used in the harvest feast contract.

The basic workshop needs no tool to construct, allowing tool production before metalworking. Toolsmiths use less timber and produce faster, but require the ore–coal–smelter chain. Tools equip new construction rather than wearing out over time.

## Placement, roads and territory

A building requires an owned, eligible tile with no other building there. Passable orthogonal neighbors must also be owned. Normal buildings stand on meadow. Fishermen may stand on meadow or sand with water somewhere in the surrounding five-by-five area. A mine must border a live matching deposit in one of the eight adjacent mountain tiles. A quarry requires a rock within radius five.

Buildings must be at least 1.9 tiles apart; headquarters placement uses 2.8. Trees and rocks on a valid building site are cleared during placement. Placement previews show validity, resource reach and expected deliveries. Outpost previews compute the additional territory through actual terrain rather than assuming an unobstructed circle.

Territory is the union of completed buildings' orthogonal land floods. Each flood is limited by its claim radius and cannot pass through water or mountains. On open land its shape is a Manhattan diamond; obstacles can reshape it. Completing, demolishing or manning a building recomputes territory. Hauling and harvesting do not themselves require territory; placement does.

Roads cost no goods. The player chooses two endpoints and the game previews a route. Road placement starts on clear owned ground and paints eligible owned tiles along that route, skipping buildings, trees and rocks. Roads do not clear obstacles. Adjacent road segments and entrances connect visually. Shift-click continues a road chain from the last endpoint.

The headquarters and last completed storehouse cannot be demolished. Demolishing a completed building refunds half its construction cost, rounded down per good; an unfinished site refunds half its delivered materials. Its remaining stock is salvaged into storage. A manned outpost also returns its soldier and one weapon. Associated jobs are unwound, reservations released and carried goods preserved or redirected.

## Transport and population

Carriers handle construction deliveries, producer ingredients, output collection and requested transfers between stores. A job carries one good. Ingredient jobs normally keep up to three units of each required input at the producer. Output delivery allows one collection job, or two when the producer has at least four output goods waiting.

Storage reservations prevent the same goods being promised twice. Pickup, reassignment and replacement-source searches respect unreserved stock and connected land. Construction jobs receive greater priority than ingredient jobs and stock transfers; construction priority settings influence their order. Soldiers travel to completed unmanned outposts, then become their garrisons.

Eight-direction A* pathfinding uses terrain costs and forbids diagonal corner cutting through impassable terrain. Its octile heuristic is scaled to the lowest movement cost. Travel speed is `2.7 / destination tile cost`, multiplied by carrier training.

| Tile condition, in precedence order | Movement cost | Base speed, tiles/second |
| ----------------------------------- | ------------: | -----------------------: |
| Road                                |           0.3 |                        9 |
| Tree                                |           1.6 |                   1.6875 |
| Sand                                |          1.15 |       Approximately 2.35 |
| Other passable land                 |             1 |                      2.7 |

Carrier capacity is `8 + 8 × (completed stores − 1)`. A new carrier can report every 15 simulation seconds while capacity and the settler reserve permit it. The reserve replenishes one settler every 15 seconds up to 40. The soldier reserve replenishes one every 40 seconds up to 20. Outposts consume soldiers from this reserve rather than converting carriers.

Warehouse stock targets request transfers from other connected stores. A source preserves its own requested reserve and existing promises. Lowering a target or pausing a producer releases unnecessary uncollected jobs; cargo already collected still arrives. Higher-priority construction and contracts can reclaim uncollected stock transfers when needed. Requested bread reserves also guide the advisor and autoplay toward additional bakery capacity, with matching grain and water supply.

## Journey, contracts and upgrades

The Colony Journey records six milestones: produce logs, produce planks, build five road tiles, produce three edible goods through fishing, baking or butchery, man an outpost and bank the first delivered gold. It provides a relevant building or road action. While an outpost awaits construction or a soldier, its action inspects that outpost.

The economy panel provides two independent upgrade tracks, each with three levels costing 15, 30 and 45 gold:

- Carrier training increases travel speed by 12% per level: `1 + 0.12 × level`.
- Workshop methods multiply production-cycle duration by `0.9^level`. Construction time is unchanged.

Contracts are optional, can each be completed once, and spend unreserved stored goods immediately:

| Contract                   | Cost                | Reward             |
| -------------------------- | ------------------- | ------------------ |
| Timber for the realm       | 12 planks           | 4 tools, 5 gold    |
| A winter provision         | 12 bread            | 8 stone, 8 gold    |
| Build the market square    | 18 planks, 18 stone | 5 tools, 12 gold   |
| Grain for the granary      | 12 grain            | 6 stone, 6 gold    |
| Beer for the harvest feast | 10 beer             | 5 tools, 12 gold   |
| Tools for the frontier     | 8 tools             | 10 planks, 10 gold |

The advisor uses current colony supply, production and transport measurements. It recommends missing chains, replanting, storage capacity and expansion; identifies stalled buildings; and distinguishes unavailable ingredients from slow delivery. Producer inspectors report cycles, stocks, inputs, output and blocked time. Settings and overlays expose routes, carrier workload, resource reach and stalls.

Producer inspectors offer **last 30 seconds**, **last 2 minutes**, **last 10 minutes** and **lifetime** rate windows for production, consumption, completed input arrivals, output actually delivered to storage, and input-blocked time. Recent history contains at most 301 cumulative snapshots sampled approximately every two simulation seconds; the inspector reports the actual covered interval rather than inventing pre-construction or pre-load time. Global pause does not age these windows, simulation speed does not change their time basis, and deliberately paused producers accrue observed idle time. Construction deliveries, starting storage goods and warehouse transfers do not count as producer input/output deliveries. Recent samples and delivery coverage persist in saves; old saves retain lifetime production but begin new, explicitly reported recent and delivery coverage on load.

Autoplay uses the same placement, economy, road and logistics functions as manual play. It evaluates every two simulation seconds, cleans up exhausted resource buildings, follows advisor deficits, expands toward needed deposits and builds supply chains. It sizes inland food supply from the grain farm’s cycle, adds wells as bakery and brewery districts grow, and seeks a new service area when an existing well’s neighborhood has no room for the needed producer. It waits for the current outpost to be manned before advancing that chain and may recycle redundant outposts or surplus farms. Holding a manual map tool suspends its planning. Enabling autoplay unpauses the game.

## Painted art and Pixi rendering

The world renderer uses **PixiJS WebGL** with native sprites, graphics, text and shader lighting. WebGL is required. If initialization fails or the graphics context becomes unavailable, the interface reports that rendering is unavailable and asks the player to reload; rendering failure pauses gameplay.

The locally shipped painted art pack contains all 22 building types, construction art, three tree species, two rock variants and a meadow material. The loader uses inspected atlas regions, transparent padding extraction and proportion-preserving placement. Building entrance anchors and logical footprints remain stable. Four growth stages retain the tree's root position. Asset installation finishes before the initial terrain paint. An artwork-loading failure reports a warning and preserves the generated procedural source artwork for the same Pixi renderer.

Ground material follows world coordinates. Cached roads, shoreline blends, connected mountain contours, crags and mineral seams remain responsive to construction and depletion. Data flows one way: simulation and tool code never paint — tile changes (cleared trees, paved roads, harvests, placement, demolition) emit a `tileChanged` event on the game event bus, and the renderer subscribes and repaints the cached static terrain tile. Presentation never writes landscape or simulation state. Painted building materials include timber, plaster, stone, clay tiles, slate and thatch. Cached village details show yards, physical stockpiles, construction progress and crop stages. Building-specific foreground surroundings add fences, gardens, barrels, sacks, timber stacks, stumps, quarry stones and fishing nets. These decorative furnishings are cached per building type and drawn after the building sprite, with open entrance corridors; cart ruts and workshop paving stay on the ground layer. Furnishings describe the workplace rather than its inventory. Settlers have directional idle/walking frames and visible cargo; walking animation follows actual movement.

Mountains combine painted angular granite peaks, warm northwest rock faces and cool shaded gullies with grassy limestone shelves at their feet. The optional mountain atlas provides three bare masses, two snowy variants and a low foothill, with crops defined in the art manifest and installation included in the atomic pack load. Cosmetic elevation reserves snow for the tallest eligible summits. Shared world-space placements cross tile boundaries and are painted into cached terrain, anchored on mountain tiles; these visual heights do not change passability, mining footprints, camera coordinates or simulation randomness. Roads and workyards remain legible, and the procedural mountain artwork remains available if the pack fails to load.

Golden-hour presentation combines warm highlights, cool projected shadows, mild sun shafts, highlight bloom and a restrained vignette. Soft contact patches ground painted buildings and tree roots independently of the existing projected cast shadows. Enclosed buildings receive restrained warm dusk auras and faint entrance light pools; open yards, wells, quarries and mines do not receive window glows. Water uses continuous world-space teal/olive pigment washes, irregular brush-stroke ripples, and a shore-distance field that blends sandy shallows across tile edges and diagonal banks. Rounded painted corners remain inside the logical water footprint. Muted beach washes, reeds and sparse lily pads soften the banks. The complete material is cached and retains its highlights at reduced quality and with Reduced Motion; full quality adds only sparse, slowly fading native reflection curves without texture swaps or raster uploads. The cosmetic day/night cycle lasts ten real minutes; weather and lighting do not affect production. Pollen, butterflies, walking dust, chimney smoke and contextual work particles add motion. Effects are bounded and respect reduced motion; reduced quality lowers particle counts, disables bloom and runs the lighting pass at reduced resolution. Pausing holds the meadow animation and stops working smoke; brief event effects can finish.

Buildings have cached alpha-contour keylines that preserve their original pixels and anchors. The optional **Visual clarity** view softens ground contrast and tree opacity without moving tree roots, uses stronger building contours, highlights existing road joins and south-facing entrance thresholds, and adds compact building-type tags with distinct working, waiting, paused, idle and construction symbols. Selecting or hovering a building reveals its full type and status. It suppresses atmospheric grading, night/weather veils, grain, vignette, projected cloud shadows and decorative particles; the cosmetic clocks continue normally. Both quality levels retain native Pixi rendering and reuse the prepared contours and terrain textures; switching views does not change simulation state or terrain.

Offscreen Canvas 2D prepares reusable artwork and terrain textures and paints the minimap. The GPU reuses cached textures and refreshes invalidated terrain with region-scoped sub-image uploads, so a single-tile change only uploads that tile's pixels. Native scene commands preserve depth ordering, camera transforms and clipping. Graphics retain their geometry when local paths and styles are unchanged, with structural (non-serialized) geometry keys; camera transforms update independently, tracked in JS rather than re-read from the canvas per shape. Sprite crop frames and text resolution update only when changed, and sprite textures are reused across crop-frame changes rather than recreated. Graphics failures during cache invalidation, resize, command capture or GPU submission pause gameplay and show an alert. Teardown releases Pixi's global GPU pools. The renderer crops terrain to the visible region, limits display resolution and throttles minimap updates. Settings reports observed frame times.

## Audio

Tone.js 15.1.22 owns local procedural synthesis, filters, modulation, the compressor and master/music/effects/ambience mix; no downloaded sound files, legacy bridge or fallback engine remain. `src/audio/audio.ts` owns one recoverable runtime and shared context. It loads Tone after interaction and owns the browser context before wrapping it so partial initialization can always close it. Readiness is published only after the complete graph starts. One-shot cues received while starting or recovering are skipped rather than queued. A failure releases partial resources and shows one nonblocking notice without interrupting play. Native context state changes detect unexpected closure during play; disposal removes the listener before closing its owned context. Audio controls retry failed playback; saved preferences apply before initialization and control changes cancel stale gain automation. Native context access is limited to browser lifecycle ownership and suspension.

`src/audio/interface-sounds.ts` owns immediate interface cues; `world-effects.ts` owns the world/economic cue catalog, cooldowns and camera/zoom-derived stereo placement. Each world cue retains its own panner. Work cues retain a six-overlap cap, 70 ms global spacing, per-kind/location cooldowns and a five-tile offscreen margin. Muted/disabled channels allocate no one-shot voices. Finite voices release their resources after playback, and victory ducking uses the shared music channel with later control changes overriding old automation.

`src/audio/ambience.ts` owns reused wind, water and rain beds, their Tone modulation and filters, plus birds, crickets, owls and thunder. Viewport water, weather and night control the mix and wildlife eligibility. `src/audio/music.ts` retains the three 48-bar pastoral themes, 96 BPM and six eighth notes per bar. Tone Transport schedules bars with audio timestamps; game code retains notes, instrument roles, eight-bar adaptive arrangement updates and smoothing for activity, input shortages, night and gold. Bars 32–39 of every theme contain no score notes, leaving ambience audible. Per-bar cosmetic variation uses its own seed; there is no custom polling scheduler.

Music and ambience use cosmetic real time and continue through ordinary simulation pause, modal display and speed changes. Hidden pages suspend playback; rapid hide/show and audio-control transitions reconcile to the latest requested state. Returning playback cancels obsolete future score voices and aligns to a phrase without a catch-up burst. New colonies, loads and audio retries retain the session-owned score cursor and read live replacement colony arrays; audio position is not saved. Audio observation and sound generation never consume gameplay RNG or advance simulation.

Economic transitions have distinct first-output, persistent-blockage and recovered-production cues, each paired with a visible colony message even when muted or audio is unavailable. High-contrast message cards stay fully readable for five real seconds before a two-second fade. The polite live log retains nodes during fading so screen readers do not announce repeated copies. A blockage must persist without output for 12 active real seconds; intentional production pauses, satisfied demand and construction reserves are not alarms. Recovery requires actual new output after an announced blockage. Matching transitions coalesce, with an eight-real-second global cooldown and a twenty-real-second per-building cooldown, keeping 8× play restrained. Paused/modal/hidden time and long unobserved frame gaps cannot mature alerts. Fresh player-action/error messages take priority. Loads establish a quiet baseline and remove stale pending notices; demolished entities cannot emit delayed recovery. `src/ui/economic-feedback.ts` owns the presentation-only observations, and `src/ui/economic-notices.ts` independently delivers their text and evidence links before attempting an optional sound. Neither module constructs or initializes audio; an absent or failed sound cannot suppress the message or interrupt the frame. One stable world-replacement subscription establishes a quiet baseline from current live state on every new colony or load, without retaining replaced arrays. The observer remains available after continuing beyond victory.

## Saving and deterministic simulation

Gameplay advances in fixed steps of 1/60 simulation second. Speed settings change how many simulation steps accumulate, rather than the size of an individual step. Long browser scheduling gaps are bounded, and hidden pages do not catch up economy time. Cosmetic animation and audio use separate clocks.

Named manual checkpoints and a separate autosave use one atomic browser-local catalog envelope (`settlers.saves.v1`). Checkpoint metadata is derived from validated colony snapshots: name, colony name, seed, wall-clock save time, simulation age, gold and building count. Manual checkpoints support rename, deliberate overwrite/delete confirmation, load and file export. Autosave replaces only its own entry every five minutes of active, unpaused play. The original `settlers.save` slot is preserved during validated legacy migration; its unknown original save time remains unavailable. The catalog limits entries and per-save/aggregate text sizes, validates each snapshot before adoption, and rejects malformed data without replacing live state.

JSON file export serializes the current colony without any browser-storage write. JSON files and base64 save codes can be imported after validation and explicit review/confirmation; imports become new checkpoints before replacing the live colony. Storage failures preserve previous valid checkpoints and prevent import adoption. A prominent top-bar save-failure control opens the save manager and file recovery path; healthy save status stays inside the save manager, with Menu save actions always available; quiet autosave successes and failures update this health without frame polling. Failed save-manager actions bring their specific error into view, including invalid imports submitted below the fold. Current-colony identity is saved separately from checkpoint names, and unsaved-progress checks compare against a successful saved or loaded baseline only on replacement actions. Preferences use a separate storage record.

Version-two saves preserve seed and gameplay RNG state, terrain and remaining deposits, roads and trees, buildings and construction progress, stocks and reservations, jobs, units and carried cargo, production timers and metrics, population timers, treasury and spent gold, upgrades, contracts, milestones and autoplay state. Supported version-one saves migrate on load. Expanded-economy saves carry an `economy: 2` marker. Existing ore remains ore. Established armories retain their ore-and-coal recipe with a persisted legacy flag; newly built armories require iron bars. New contract indexes are appended so completed original contracts remain completed. Loads validate and prepare the full replacement before committing; invalid data does not partially replace a running colony. `src/core/persistence.ts` owns the save wire format and accepts an injected storage adapter for the catalog and legacy slot. A committed load replaces authoritative state, recomputes territory, then publishes `worldLoaded`. Renderer, inspector, HUD, message cache and application loop subscribers reset their own transient views and accumulator; persistence never calls presentation methods. Renderer caches, transient visual effects, selection and hover state are rebuilt rather than treated as authoritative save data.

Compatibility retained intentionally: save validation accepts the current building-specification ingredients plus historical exceptions. Thus a legacy armory save can contain iron-bar fetch cargo as well as iron ore, and an unversioned toolsmith save can contain iron bars as well as planks and stone, even though the migrated recipes consume different ingredients. This broader acceptance is preserved separately from live production eligibility; tightening it requires a separate compatibility decision. The mine inspector also retains all known goods present in historical input metrics rather than filtering history to currently eligible meals.

`src/gameplay/production-rules.ts` owns pure recipe interpretation shared by economy, advisor, inspector and economic feedback: nominal recipe requirements, eligible ingredient alternatives, ingredients selected for the next cycle and comparisons identifying current ingredient shortages. Readiness, status and persistent notices query the same shortages; feedback revalidates them against stock after carrier arrivals, so a same-step delivery can clear a stale input-blocked reason before a notice. Mines request every edible kind but consume the most plentiful, breaking ties in bread, meat, fish, provisions order; an empty pantry retains the provisions shortage diagnosis. Save validation shares edible alternatives while retaining its separate historical acceptance rules.

Advisor policy and road mutations belong to the domain and are shared by manual play and autoplay. Progression rules own milestone checks, spending, contracts and upgrades, while `ui/progression-view.ts` owns their DOM views.

`src/gameplay/colony-rules.ts` owns shared well coverage, territory projection, producer output capacity and colony reserve thresholds. Well coverage always uses the building table's well radius over connected land and has two explicit meanings: **planned coverage** counts finished wells and wells under construction, so planning does not order a second well; **active service** requires a finished well and decides production. Paused wells count for neither. One territory projection computes borders, both guard-preview variants and autoplay's useful/redundant guard checks; a hypothetical source list can add, remove or unman guards without changing the colony. The unmanned guard radius has one definition. The rules are pure queries over the live colony and consume no RNG.

Base production cycles live in the building table. Scheduling, status, production observations and progress reports share the output-capacity and reserve rules. The economy's `buildingWorking` query combines current scheduling constraints with the last recorded blockage; the renderer uses it for work motion and work indicators rather than maintaining its own production rules. The query changes no timers, stocks, recorded reasons or RNG.

Production block reasons share the closed `ProductionBlockReason` type across buildings, scheduling, progress reports and observation subsets: `paused`, `exhausted`, `output`, `demand`, `reserve`, `water`, `inputs` and `resources`, with the empty string meaning no blockage. Saves retain these existing string values; loading an absent, unknown or legacy reason normalizes it to the empty string before replacing live state.

The economy shares one fetch-count helper, carrier-reset operation and nearest-storage search. Storage searches retain each caller's available-stock, reserve, connectivity and exclusion requirements, choosing the first eligible store on equal distances. Demolition computes a current quote and applies its refund, salvage and receiving stores rather than recalculating them independently; cancellation still returns dispatched soldiers and redirects carried goods through the existing job lifecycle.

`src/simulation/roads.ts` owns road planning as well as construction: preferred route selection, rejection reasons and paving eligibility share one implementation. Existing start-tile and neighbor notifications, road counts and milestone ordering are preserved, including successful roads that add no pavement. The renderer consumes the plan while retaining hover state, preview caching, labels and the travel-time calculation shared with building-placement previews; estimates still compare travel along the original route rather than rerouting after hypothetical paving.

Preview/status queries emit no feedback. `ui/domain-feedback.ts` owns action messages, sound and effects. `ui/messages.ts` owns real-time deduplication and the eight-message feed plus an external WeakMap status cache; autoplay reads fresh domain status. `ui/interaction.ts` owns coordinated tool, selection, tile-detail, road-anchor and demolition-confirmation transitions as well as hover and presentation preferences. Map and inspector razing share confirmation while domain commands retain protection rules. Shift-road input advances its anchor only on successful construction; ordinary attempts clear it. Advisor focus retains the tool and tile detail, flagged navigation retains the tool but clears tile detail, and Journey outpost inspection cancels the tool. DOM routing, hit testing, camera moves and view painting remain with the HUD and Journey view. The renderer owns static/border invalidation flags. Territory and tile events invalidate consumers' own caches. Passive presentation observers isolate/report effect failures so they cannot interrupt domain mutations; domain listener exceptions remain synchronous and propagate. Subscriptions are installed once, and loads reset consumers rather than reinstalling listeners.

`src/ui/catalog-view.ts` owns persistent search/filter controls, illustrated catalog cards and the live DOM placement panel. The renderer shares cached placement and road predictions with the production panel while retaining typed internal hooks for focused tests.

`src/ui/workspace.ts` owns presentation workspace navigation, contributor inspection versus explicit location, removed-selection context, and nested utility/focus layers.
