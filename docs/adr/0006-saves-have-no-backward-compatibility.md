# Saves use one current structure

Decided on 2026-10-17 ([#55](https://github.com/teodoryantcheff/ai-settlers/issues/55)); revised on 2026-10-18 ([#71](https://github.com/teodoryantcheff/ai-settlers/issues/71)) after confirming a clean break with every existing save. Use one unversioned save format, validated against the current structural and semantic requirements. Snapshots, checkpoint catalogs, autosaves and their browser-storage keys have no revision identifiers. There are no migrations, historical aliases or load-time defaults. This keeps compatibility machinery from constraining an actively developed game whose saved colonies need no continuity guarantee across changes.

Fresh, unnumbered storage keys ignore every pre-change browser save without reading or deleting it. Explicit imports containing former snapshot markers are rejected with a clear error before stored checkpoints or the live colony change. Later saves load whenever they satisfy the current structure, regardless of the build that wrote them; incompatible data fails validation rather than selecting another reader.

The checkpoint catalog remains one atomic envelope: a catalog containing an invalid checkpoint is unavailable until deliberately cleared. A damaged separate autosave is reported without hiding named checkpoints. Validation before adoption, exact seeded continuation of accepted saves, and live runtime bindings across loads remain required.
