# Saves have no backward compatibility

Decided on 2026-10-17 ([#55](https://github.com/teodoryantcheff/ai-settlers/issues/55)). Only the current save format loads. A save written by an older release, or one missing any field the current snapshot writer emits, is rejected with an explicit error before the live colony or stored checkpoints change. Nothing is migrated, aliased or defaulted at load.

Save compatibility had accumulated as inline migration inside the shared validation boundary: version-one saves, unversioned pre-expansion economies, historical building and job field aliases, an autosave stored inside the checkpoint catalog, the original single browser slot, and legacy armory recipes and cargo kept alive as persistent gameplay state. Each path needed its own tests and constrained later changes. The game is in active development with no player base whose colonies must survive upgrades, so a cleaner, stricter boundary is worth more than continuity of old saves.

When the save format changes, either bump the version and reject the old one, or add a deliberate, tested migration as its own decision. Stale storage keys from older releases are ignored rather than read or deleted. The checkpoint catalog is still validated as one envelope, so a catalog that holds an unsupported checkpoint is reported as unavailable, as a corrupt catalog already was; clearing it is a deliberate manual step. Validation before adoption, exact seeded continuation of current saves and live runtime bindings across loads remain required; this decision narrows what is accepted, not those guarantees.
