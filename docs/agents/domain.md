# Domain docs

This repository uses a single context: `GLOSSARY.md` at the root and decisions in `docs/adr/`.

Before exploring a domain, read the glossary and ADRs relevant to that area. If a document is absent, proceed silently; `domain-modeling` creates domain documents when terms or decisions are resolved.

Use the glossary's vocabulary in issue titles, designs, hypotheses and tests. If a concept is missing, reconsider the term or note the gap for `domain-modeling`.

Surface proposals that contradict an ADR explicitly, naming the decision and explaining why it should be reopened.
