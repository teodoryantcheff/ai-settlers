# JavaScript library options

Research checked against official documentation on 2026-10-15. This is an assessment of possible uses, not an adoption or architecture decision. None of the packages below appears in the current `package.json` or `package-lock.json`.

The project already has PixiJS, TypeScript, esbuild, Playwright and Node tests. Useful additions should address a specific maintenance cost or desired feature. The fit assessments below are engineering judgments based on the repository; linked documentation establishes library capabilities.

| Library | Verified capability | Conditional fit in this project |
| --- | --- | --- |
| **fast-check** | Generates test inputs and shrinks failures to smaller counterexamples; works independently of the test runner. Failures can be replayed with a seed and counterexample path. [Getting started](https://fast-check.dev/docs/introduction/getting-started/), [core blocks](https://fast-check.dev/docs/core-blocks/), [parameters](https://fast-check.dev/docs/api/interfaces/Parameters/) | **Strong first candidate.** Exercise save/load continuation, malformed imports, reservation bookkeeping and road-plan invariants over many generated cases. Keep it a development dependency, compose the real graph through `tests/helpers/game.cjs`, bound case sizes and retain replay details. Its test-data randomness must remain separate from simulation RNG. |
| **Floating UI** (`@floating-ui/dom`) | Provides framework-free anchored positioning, viewport collision handling and automatic updates on layout changes. `autoUpdate` requires cleanup when the popup closes. Its accessible interaction primitives belong to its React package. [Getting started](https://floating-ui.com/docs/getting-started), [computePosition](https://floating-ui.com/docs/computeposition), [autoUpdate](https://floating-ui.com/docs/autoupdate) | **Strong, narrow candidate.** Could replace manual rectangle/clamping geometry in `src/ui/transient-help.ts`. Retain the existing hover, keyboard focus, pointer-enter, Escape and dismissal policies; adding the DOM package does not supply those policies. Useful if current positioning needs more edge-case handling. |
| **Dexie.js** (`dexie`) | Provides IndexedDB access from ordinary JavaScript modules, indexed queries and transactions that group database operations atomically. Unrelated asynchronous work inside a transaction can cause it to become inactive. [Module use](https://dexie.org/docs/Tutorial/Consuming-dexie-as-a-module), [transaction practices](https://dexie.org/docs/Tutorial/Best-Practices) | **Useful when save storage grows.** Could store individual save slots, autosave generations and optional thumbnails instead of rewriting the entire localStorage catalog. `src/core/save-catalog.ts` currently exposes synchronous storage: this would require an asynchronous storage/migration design. A database transaction does not validate a save or make live-state adoption atomic; preserve validation before adoption and visible failure reporting. |
| **Zod** (`zod`) | Runtime schemas produce validated data, structured errors and inferred TypeScript types. Parsing returns a deep clone. Zod documents TypeScript `strict` mode as required. [Basics](https://zod.dev/basics), [requirements](https://zod.dev/#requirements) | **Useful validation direction, with a prerequisite.** Could consolidate save-envelope and art-manifest boundary validation. The project enables `strictNullChecks` but still sets `strict` to `false`; resolve that compatibility before treating Zod as a small addition. Preserve legacy migrations, cross-reference checks, rejection semantics and live bindings; a shape schema alone does not enforce those contracts. |
| **Fuse.js** (`fuse.js`) | Performs client-side typo-tolerant search over chosen object fields and ranks results, with configurable fuzziness and field weighting. Supports plain JavaScript module imports. [Getting started](https://www.fusejs.io/getting-started.html), [fuzzy search](https://www.fusejs.io/fuzzy-search.html) | **Small feature option.** Could improve building-palette or reference search using names, recipes and descriptions. Adopt for a concrete need such as finding a building despite a typo; a small fixed catalog may be adequately served by existing substring filtering. Tune thresholds and prioritize names so loose matches do not obscure obvious choices. |
| **Chart.js** (`chart.js`) | Supports plain JavaScript integration, selective component registration and updating existing charts. Updates can disable animation with `update('none')`. Charts render to Canvas and require accessible alternatives. [Integration](https://www.chartjs.org/docs/latest/getting-started/integration.html), [updates](https://www.chartjs.org/docs/latest/developers/updates.html), [accessibility](https://www.chartjs.org/docs/latest/general/accessibility.html) | **Lower priority unless analysis becomes richer.** `src/ui/economy-view.ts` already has a compact SVG step chart. Chart.js becomes more attractive for additional chart types, multiple series and richer inspection. Restrict it to report charts, preserve textual totals, observation gaps, simulation-time axes and Reduced Motion. It must not replace the PixiJS world renderer. |

Two further options depend on a substantial feature or maintenance need:

- **Tone.js** offers synthesizers, effects and a transport for scheduling interactive music, with ordinary module imports and user-gesture audio startup. It is relevant to the existing procedural Web Audio implementation in `src/audio/audio.ts`, but migration would be substantial. Consider it when expanding musical composition or reducing synthesis maintenance; keep audio timing and cosmetic randomness outside the simulation. [Official introduction](https://tonejs.github.io/)
- **interact.js** offers dragging, resizing, snapping and movement restrictions without requiring a UI framework. It emits interaction data; the application still applies styles and owns state. It could simplify `src/ui/report-windows.ts` if window interactions expand, while preserving focus handling, reachable title bars and session geometry. [Official documentation](https://interactjs.io/docs/)

The relevant constraints remain [ADR-0003](adr/0003-preserve-economic-observation-history.md), which preserves economic observations across saves, and [ADR-0004](adr/0004-full-map-and-game-windows.md), which specifies live reports, contextual help and shared interaction policies. None of these options requires reopening either decision if integrated within those boundaries.

No packages were installed and no runtime behavior changed. Dependency size, performance and migration cost have not been benchmarked; those would need evaluation against a concrete proposed integration.
